# Публикация

## Любой статический хостинг

Распакуйте архив. Загрузите всё содержимое в папку публикации так, чтобы index.html находился в её корне. Сборка не требуется. Все пути относительные — проект работает и в подпапке сайта.

## GitHub Pages — демонстрационные сайты

1. Войдите в GitHub и создайте репозиторий для демоверсии.
2. Нажмите Add file → Upload files.
3. Распакуйте ZIP у себя на компьютере. Перетащите **всё содержимое распакованной папки**, включая папки assets, css, js, docs, tools, и файлы index.html, config.js, README.md, LICENSES.md, robots.txt, .nojekyll. Через файловый менеджер папки можно перетаскивать целиком. Не перетаскивайте только один ZIP-файл.
4. Убедитесь, что index.html лежит в корне репозитория, а не на дополнительном уровне папки.
5. Сохраните изменения кнопкой Commit changes.
6. В Settings → Pages выберите Deploy from a branch, ветку main, папку / (root), затем Save. Если названия пунктов интерфейса изменились, найдите настройки источника публикации Pages.
7. Дождитесь успешной публикации и откройте ссылку, которую покажет GitHub. Адрес не нужно угадывать.
8. Проверьте изображения, выбранного спутника, шрифты и сохранение грамоты. Если фон пропал, проверьте, что assets загружена полностью и регистр букв в именах файлов сохранён.

GitHub Pages не предоставляет закрытый доступ к обычному публичному демосайту. Для фото реальных детей и обещанной приватности выберите подходящий закрытый хостинг. Закрытый репозиторий сам по себе не гарантирует, что опубликованный сайт закрыт.

## Эта версия в Sites

Создан отдельный приватный Site. Новые копии заказов следует создавать отдельно и проверять их доступ до передачи ссылки. Исходный репозиторий и настройки Sites не входят в клиентский ZIP, поэтому переносимый архив можно использовать независимо.
